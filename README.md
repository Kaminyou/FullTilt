## Environment Preparation
Note: some dependencies' versions can be modified to match your own requirement. For example, python's version can be 3.10 and scipy's version can be unspecified. Please modify `environment.yaml` if needed.
### Option 1: Use a Pre-Built Docker Image
```sh
# please make sure you have gdown (pip install gdown)
./download_docker_image.sh
docker load < fulltilt_training.tar  # for training and inference
```

### Option 2: Build a Docker Image from Scratch
```sh
docker build -t <IMAGE_NAME:TAG> .
```

### Option 3: Conda
```sh
conda env create -f environment.yaml -n fulltilt
conda activate fulltilt
pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu124
pip install torchvision==0.20.1 timm==1.0.20

# make sure you have the `CUDA_HOME` environment variable by `echo $CUDA_HOME` first
# set up TORCH_CUDA_ARCH_LIST according to your need
export TORCH_CUDA_ARCH_LIST="7.0;7.5;8.0;8.6;8.9;9.0+PTX" 
pip install -e . --no-build-isolation
```

### Sanity check
#### E2E Test (Sanity Check for Inference)
```sh
./prepare_e2e_test.sh
pytest tests/test_e2e_pipeline.py -v -s
```

#### Sanity Check for Training
```sh
./train.sh 1 configs/cfg_cryo.py configs/dataset.json outputs_test
# You can stop it after some epochs
```

## Get Started
*Caveat: While FullTilt is an open-set detection framework, its current performance on diverse datasets is limited by the narrow training distribution of the simulation data. We recommend fine-tuning on your datasets if there is a significant distribution gap.*
### Intra-Instance Inference
Please see `example.py` or `example.ipynb`. Required data and pretrained weights can be downloaded via `./prepare_e2e_test.sh`.

### Cross-Instance Inference
Please see `example_cross_instance.py` or `example_cross_instance.ipynb`. Required data and pretrained weights can be downloaded via `./prepare_e2e_test.sh`.

### Training / Fine-Tuning
For fine-tuning, please add `--pretrain_model_path weights/fulltilt.pth` to `./train.sh`.
```sh
./train.sh <GPU_NUM> <CONFIG_PATH> <DATASET_JSON_PATH> <OUTPUT_PATH>
```
For example
```sh
./train.sh 4 ./configs/cfg_cryo.py ./configs/dataset.json test_outputs
```
#### Notes
- A `--shm-size=8g` flag might be set for training if you are using the docker image.

## Prepare data for training / fine-tuning (and evaluation in the training pipeline)
Each dataset should be organized in the following format
```
ROOT_FOLDER/
|- datasetA/
|- datasetA_anno.json
|- datasetA_coco.json
|- datasetA_group23dgt.json
|- datasetA_group.json
|- datasetA_map.json
|- datasetB/
...
```
Take `datasetA` as an example. `datasetA` folder contains tilt-series images. We need to prepare
`datasetA_anno.json`, `datasetA_map.json`, and `datasetA_group23dgt.json`. `datasetA_coco.json` and
`datasetA_group.json` are generated by using `tools/odvg2coco.py`.

Let see an example
- `datasetA_anno.json` is LIST[LIST[DICT]]: a dataset is a LIST of tilt-series; a tilt-series is represented by a LIST of DICT.
```bash
[
    [
        {
            "filename": "datasetA/FILENAME_OF_THAT_TILT_IMAGE",
            "height": 512,
            "width": 512,
            "within_group_id": 0,  # NOTE THIS GROUP ID
            "tilt": -60.0,
            "detection": {
                "instances": [  # NOTE THE ORDER
                    {
                        "bbox": [
                            251,
                            45,
                            261,
                            55
                        ],
                        "label": 0,
                        "category": "proteinZ"
                    },
                    ...
                ]
            }
        },
        {
            "filename": "datasetA/FILENAME_OF_THAT_TILT_IMAGE",
            "height": 512,
            "width": 512,
            "within_group_id": 0,
            "tilt": -57.0,
            "detection": {
                "instances": [...]
            }
        },
    ],
    [
        ... ANOTHER TILT SERIES
    ]
]
```
- `datasetA_map.json` defines a mapping from integer label (string) to the label name (string).
```bash
{
    "0": "proteinZ",
    "1": "proteinY",
    "2": "proteinX",
    ...
}
```
- `datasetA_group23dgt.json` is DICT[DICT]: the group ID (string) -> 3D ground truth of that group.
Each group has `3d_positions`, `tomogram_size`, `particle_sizes`, `categories`, and `labels`. Please
note that the number of items within `3d_positions` should be the same as `particle_sizes`,
`categories`, and `labels`. Also, the order of them (corresponding to the object within 3D space)
should be the same order as they are in each tilt image represented in `datasetA_anno.json`.
```bash
{
    "0": {
        "3d_positions": [
            [
                300,
                330,
                130
            ],
            ...
        ],
        "tomogram_size": [
            512,
            512,
            200
        ],
        "particle_sizes": [
            13,
            ...
        ]
        "categories": [
            "proteinZ",
            ...
        ],
        "labels": [
            0,
            ...
        ]
    },
    "1": {...}
    ...
}
```
After you have all of them, execute:
```sh
python3 tools/odvg2coco.py ROOT_FOLDER/datasetA_anno.json datasetA
```
The sciprt will generate `ROOT_FOLDER/datasetA_coco.json` and `ROOT_FOLDER/datasetA_group.json` for
you.

Finally, you can specify them in the training datasets config:
```json
{
  "train": [
    {
      "root": "ROOT_FOLDER/",
      "anno": "ROOT_FOLDER/datasetA_coco.json",
      "group_file": "ROOT_FOLDER/datasetA_group.json",
      "group_3d_file": "ROOT_FOLDER/datasetA_group23dgt.json",
      "label_map": null,
      "dataset_mode": "coco"
    }
  ],
  "train_random": [
    {
      "training_generation_num": INT,
      "dataset_mode": "random_coco"
    }
  ],
  "val": [
    {
      "root": "ROOT_FOLDER/",
      "anno": "ROOT_FOLDER/datasetB_coco.json",
      "group_file": "ROOT_FOLDER/datasetB_group.json",
      "group_3d_file": "ROOT_FOLDER/datasetB_group23dgt.json",
      "label_map": null,
      "dataset_mode": "coco"
    },
    {
      "root": "ROOT_FOLDER/",
      "anno": "ROOT_FOLDER/datasetC_coco.json",
      "group_file": "ROOT_FOLDER/datasetC_group.json",
      "group_3d_file": "ROOT_FOLDER/datasetC_group23dgt.json",
      "label_map": null,
      "dataset_mode": "coco"
    }
  ]
}
```
We currently support one training dataset (or you can merge several datasets into one).
`train_random` block can be deleted if you don't need it. For `val` block, we support multiple
datasets for evaluation.
